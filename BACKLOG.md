# Backlog — maintenance registry for `theokit-plugins`

One registry, at this repository's root, covering every package under `packages/`. It does **not**
span other repositories: `theokit`, `theokit-sdk`, `theokit-ui` and the rest of the org each own
their own, per `.claude/rules/knowledge-base-location.md § Autonomy`. A finding about the framework's
plugin API belongs in `theokit`, not here.

Ids are monotonic and **never renumbered** — a killed item keeps its number forever, because the
number is the audit trail.

## How an item gets here

Two producers, one schema: `/backlog-item` (the human door — a hypothesis, no evidence required) and
`/discover --sweep` (a measured finding, evidence already attached). The schema contract lives in
`.claude/rules/cycle-backlog.md`; this file is data.

**Routing is not duplicated here.** `.claude/scripts/route_domain.py` parses the `## Domain routing`
table in the rule and nowhere else — one table, one truth. A copy in this file would drift, and the
script's own history records what that costs: a second three-column table once parsed as routing and
invented two domains whose specialist files were never written, with nothing objecting.

Check a routing before filing:

```bash
python3 .claude/scripts/route_domain.py plugin-payments --json
```

## Why the items below say `evidence: none-yet`

Every item here was noticed while measuring something else, and the measurement is recorded in
`why_now` with its pointer. `evidence` stays `none-yet` because **DISCOVER has not run** on any of
them: the field means "a measurement this cycle performed and stands behind", not "the filer knows
something". Filling it before the cycle runs is the evidence theatre the rule names as an
anti-pattern, and it would let a plan be justified by a hunch wearing a citation.
